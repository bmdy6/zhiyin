# 微信聊天知识库更新流程

这套流程由一次“更新微信聊天知识库”的请求触发：取得本次离线副本，导出消息，沿用已有联系人编号和分组，核验后写回。聊天、密钥、路径配置和关系判断保存在本机；公开项目只维护通用代码。

## 一、先确定本次输入

先读本机 `~/.config/wechat-mac-export/profile.json`，核对项目、账号数据目录、已有密钥文件、知识库私有目录、工作目录和现有虚拟机。没有配置时再补齐缺少的路径。配置只存路径，不存密钥值。

每次使用新的工作目录，记录微信版本、副本取得时间、旧清单的统计时刻，以及原有分组文件的版本。确认私有聊天目录被知识库 Git 忽略。

已有微信 4.2.0 数据及配套密钥时直接走下面的离线流程；实际版本不同，先验证兼容性。已有密钥通过当前副本校验后，无需重新登录微信或启动虚拟机取钥。

## 二、复制本次加密快照

以下路径都是占位示例。`SOURCE` 必须是本次选定账号的 `db_storage`，`WORK` 必须尚不存在，且位于仓库及微信容器之外。

```sh
REPO="/path/to/wechat-mac-export"
SKILL_DIR="/path/to/installed/wechat-mac-export"
SOURCE="/path/to/account/db_storage"
KEY_FILE="/path/to/local/master.key"
CURRENT="/path/to/knowledge/private/chats"
WORK="/path/to/private/work/new-run"
CLI="$REPO/.venv/bin/wechat-mac-export"

umask 077
mkdir -m 700 "$WORK"
"$CLI" snapshot --source "$SOURCE" --output "$WORK/snapshot"
```

`SKILL_DIR` 指向当前使用的技能目录，独立安装时使用安装目录；直接在含此流程的新版本仓库中使用时，也可设为 `$REPO/skills/wechat-mac-export`。`REPO` 负责提供离线导出 CLI，不要求它与技能位于同一目录。

首次使用时，按项目 README 建立 `.venv` 并安装项目。后续使用已有环境，不依赖全局 Python 是否安装了项目依赖。

`snapshot` 会复制所需数据库及 WAL/SHM，并比较复制前后源文件与副本的哈希。源文件变化时本轮停止，换用稳定副本或选择合适时机重新复制。

若 macOS 拒绝终端读取目录，可通过 Finder 正常复制到本次私有工作目录，保留账号上层目录。无法直接核对源文件时，分别从同一来源复制两次，比较相关数据库及 WAL；一致后仍须完成后面的密码学与 SQLite 检查。两份一致不代表全目录的原子快照，不能省略后续检查。

## 三、验证密钥并离线导出

```sh
"$CLI" verify --snapshot "$WORK/snapshot" --key-file "$KEY_FILE" \
  --handoff-dir "$WORK"

"$CLI" export --snapshot "$WORK/snapshot" --key-file "$KEY_FILE" \
  --output "$WORK/export" --handoff-dir "$WORK"
```

所有数据库首页 HMAC 通过后才能继续。导出会逐页认证、恢复完整提交的 WAL 事务，并对解密库执行 SQLite `quick_check`。密钥不存在、不匹配或库检查失败时，保留旧知识库，停止写回。

此处得到完整 JSONL、Markdown、清单和基础统计。媒体保留类型占位，群聊及附件不属于当前工具的导出范围。记录本次副本中的最新消息时间，避免把处理完成时间当成数据截止时间。

## 四、沿用已有知识库结构

已有知识库的 `导出清单.json` 是联系人身份与编号的对照表；不能按本次聊天量重新编号。以 `conversation_id` 关联历史，保留旧编号、代号、目录和原备注，新联系人从历史最大编号后追加。

```sh
python3 "$SKILL_DIR/scripts/refresh_knowledge.py" prepare \
  --export "$WORK/export" --current "$CURRENT" \
  --output "$WORK/prepared"
```

准备阶段检查旧记录的覆盖及重复次数，缺失历史时拒绝覆盖。它复制完整旧目录，保留独立备注、人工分组、旧分析素材与映射；JSONL 更新为完整时间序，已有 Markdown 保留原文和人工备注，只在末尾增补本次新增消息。统计、清单和分组索引重新生成。

核对以下结果：

- 旧联系人编号、代号和目录均稳定；新编号只追加。
- 历史记录覆盖检查通过；JSONL 总行数与清单一致，目录与 Markdown 数量一致。
- 人工分组及独立备注未被改写，旧代号表原文保留。
- 分组索引与原分组文件一致，原有推断仍保留来源与待确认状态。

核验通过且用户已要求更新后，执行写回：

```sh
python3 "$SKILL_DIR/scripts/refresh_knowledge.py" apply \
  --prepared "$WORK/prepared" --current "$CURRENT" \
  --backup "$WORK/before-refresh"
```

`apply` 再次校验原目录及暂存目录的版本，保留完整旧目录后替换。准备期间有人修改任何文件时，重新准备，不覆盖新编辑。不要直接编辑暂存目录再执行 `apply`，其版本指纹会拒绝该变更。

## 五、按授权补充分组

正常更新先复用原有分类。用户已允许依据聊天补充分组时，重点查看新联系人及仍待确认的联系人，不重复判断已经由本人确认的关系。

先看初次联系、最近交流及关系相关片段，必要时补看中间上下文，并与已有知识记录交叉核实。昵称、称呼和聊天频率不能单独证明亲属、雇佣或亲疏关系。记录实际阅读范围，不把抽样说成通读全部历史。

分组文件使用二级标题和固定编号列表。例如：

```markdown
## 同学
- 001 联系人甲：共同课程与作业往来——聊天明确

## 朋友
- 002 联系人乙：日常交流，实际认识背景待核实——AI 推，待确认

## 待确认（信息不足）
- 003 联系人丙：只有好友验证，无法确定关系——信息不足，待确认
```

依据分为“用户标”“聊天明确”“按备注/昵称”“AI 推，待确认”。“聊天明确”说明消息直接支持该来往背景；不把对方自述当作已经核验的职务、资质或其他官方事实。保留本地消息文件和行号，必要时单列分组依据。即使昵称相同，也不自动合并账号。

新联系人先通过第四步获得稳定编号，再补充分组。补充分组原文前先读原文、保存差异与版本条件；仅修改获授权的原始私有聊天资料。随后用同一份本次导出再准备和写回一次，使用新的目录：

```sh
python3 "$SKILL_DIR/scripts/refresh_knowledge.py" prepare \
  --export "$WORK/export" --current "$CURRENT" \
  --output "$WORK/grouped-prepared"

python3 "$SKILL_DIR/scripts/refresh_knowledge.py" apply \
  --prepared "$WORK/grouped-prepared" --current "$CURRENT" \
  --backup "$WORK/before-group-index-refresh"
```

这样新分组有稳定的身份绑定，派生索引也会更新。正式 `personal/`、`company/` 知识文档的变更继续走知识库 MCP，不使用此脚本写入。

## 六、完成后的回读

从知识库原路径重新打开清单、分组、索引与统计，核对人数、消息数和新增量；确认私有目录仍被 Git 忽略、没有本次遗留的明文 SQLite 临时目录。启动或恢复过的虚拟机恢复到原先状态。

本地路径配置的 `last_success` 仅在写回与回读通过后更新，同时记录本次工作目录 `last_run_dir` 和最后一次完整备份路径 `last_backup`。一次结果汇报应包含：

1. 副本取得时间及最新消息时间。
2. 总会话数、消息数和相对上次的新增量。
3. 保留的既有结构、补充分组数量及仍待确认的情况。
4. 本地阅读入口、完整备份位置及未完成事项。

旧分析素材继续保留其原截止时间；没有重新生成分析，就不称分析已经更新。

## 七、异常接力与回滚

| 情况 | 处理 |
| --- | --- |
| 读取权限不足 | 保留现状，经正常文件访问取得本次副本；不当成账号不存在 |
| 复制中源文件变化 | 重新取得稳定副本，不继续处理不一致输入 |
| 密钥不可用 | 停在写回前；检查账号、版本与已有密钥，再进入已授权的虚拟机接力 |
| 需要登录或扫码 | 只有官方界面实际要求时交给本人操作 |
| 历史记录缺失 | 保留旧目录与两份证据，不猜匹配、不删除历史 |
| 原目录或暂存被修改 | 保留新编辑，重新准备和核验 |
| 写回后需回退 | 保留当前目录作为现场，再把选定的完整备份恢复到原路径并回读 |

回滚后同步修正 `last_success`，不保留错误的成功标记。备份和加密快照的清理另行处理，不在例行更新里自动删除。

虚拟机是隔离环境，不会自动提供数据库密钥。当前工具复用已授权密钥，不包含新的自动取钥程序；已有取钥流程产出的候选仍须对当前消息库和联系人库通过 HMAC 校验。宿主机 SIP 和现用微信不因离线导出而调整。
